## ⭐ Comment il RÉCUPÈRE et TRAITE les données (le levier pour la recréation)
**DB de description unique** : `std::map` à **0x01255130** (root 0x01255138), clé = id item/skill, **~27 221 entrées live**. Lookup = `ItemSkillDescDB_Lookup` (0x006a0d40) → record à node+0x14, ou nil. Chargement paresseux : `ItemSkillDescDB_EnsureLoaded` (0x006a06b0, cache DAT_0125510c, parse via mgr DAT_01255108).

**Record fields** : +0x08 nom skill / +0x0c lignes-desc skill ; +0x1c nom item / +0x20 lignes-desc item. Le flag struct+0x5c choisit la paire.

**Accesseurs (prennent un `ItemSkillInfo*`)** :
- ⚠️ `ItemSkillDB_GetResName` (0x006a4bc0) → C-string **resname** (PAS le nom affiché ; rec+0x1c item / rec+0x08 skill). Sert au chemin **image collection** : `DAT_0102f964` = `유저인터페이스\collection\` + resname + `.bmp` → wnd+0x1c4, blit à (10,11). (Anciennement mal nommé GetName.)
- `ItemSkillDB_GetDescLines` (0x006a2a70) → vecteur de lignes (C-strings ; peuvent contenir des tokens couleur `^RRGGBB`).
- **Nom affiché** = `ItemSkillInfo_BuildDisplayName` (0x008a0570) : compose nom de base (`ItemSkillInfo_GetBaseName` 0x006a2b50) + refine "+N" (struct+0x18) + grade (struct+0x22) + slots "[N]" + enchant/option, en **segments colorés** (out couleur 0xe04040/0x4040e0/normal) consommés par `UIItemSkillDescWnd_DrawName` (0x008972c0). C'est la source autoritaire du titre pour une réimpl ImGui.
- `ItemMoveInfo_GetByItemId` (0x006a2bf0, ex-« ItemSkillDB_GetStockRec » ERRONÉ) → **PAS un stock/count** : renvoie le record de flags de déplacement de l'item (drop/trade/store… depuis ItemMoveInfoV5.txt, map `g_ItemMoveInfoMap` 0x01255110), node+0x14 ; fallback record zéro. Ce qui « gate le label count » en DrawContent teste en réalité un flag de move-info. Cf la fiche supprimee.

**Le struct `ItemSkillInfo`** (~0xf4 o, 2 std::string MSVC SSO) : +0x2c = resname/id en chaîne décimale (entrée lue par atoi), +0x40 = cap string, +0x44 = nom affiché, +0x5c = flag skill. Helpers : `ItemSkillInfo_ctor` (0x006a1b20), `ItemSkillInfo_SetId` (0x006a6570, itoa id→+0x2c), `ItemSkillInfo_GetId` (0x005d98a0), `ItemSkillInfo_Copy` (0x006a25f0).

**⭐ Accès STANDALONE** (clé pour réimplémenter sans la fenêtre native) : construire un `ItemSkillInfo` (ctor + SetId(id)), poser +0x5c=1 pour un skill, puis `GetDescLines` (texte) + `ItemSkillInfo_GetBaseName`/`BuildDisplayName` (titre) + `GetResName` (image collection). Aucune fenêtre requise.

**Extraction depuis un item d'inventaire/équipement** : `ItemSkillInfo_BuildFromSlotList` (0x0085b630, depuis *param_1=1er record d'une liste de slots) et `ItemSkillInfo_BuildFromItemRecord` (0x008283a0, depuis un record DB) remplissent le struct : ResolveItemResNameById(record+8=id), resname, refine, **cartes** (FUN_006a6af0), **options aléatoires** (FUN_006a65d0), flags ; rejettent les items « unknown item ». ## ⭐⭐ NOM « ROUGE » d'un item CASSÉ = OMBRE rouge (RE live x32 2026-07-08) — RÉSOLU
Le « nom rouge » d'une **arme cassée** (durabilité) N'EST PAS la couleur du TEXTE — c'est l'**OMBRE**. `DrawName` (0x008972c0) dessine chaque segment avec texte+ombre via `FUN_00a27c20(...,textColor,shadowColor,...)`. Pour un segment non-highlight, l'ombre dépend de **`info+0x5d`** :
- `info+0x5d == 0` → couleur de grade (FUN_006a2990) + ombre BLANCHE.
- **`info+0x5d != 0` → texte = param_4 (défaut, ex. NOIR) + ombre = `0x5050fa`** (COLORREF **BGR** → RGB **250,80,80 = ROUGE**). ⇒ texte noir + ombre rouge décalée = le nom paraît « rouge ».
- (highlight/forgé : ombre 0xe0e0e0.)
Preuve live (arme Rapier 1110 cassée, desc ouverte, BP sur BuildDisplayName 0x008a0570) : `colorOut` = **0x30 (garbage, NON écrit)** ⇒ pas de highlight ; `param_4` (couleur texte, DrawName [ebp+0x14]) = **0 (NOIR)** ; `info+0x5d` = **1**. Donc texte NOIR, ombre ROUGE. `info+0x5d` est mis à 1 pour l'item cassé (probablement par un **paquet** de statut cassé — l'utilisateur avait raison « you must miss a packet »). ⚠️ La fiche ItemSkillInfo ne porte AUCUN champ « broken/attribute » exploitable directement (BuildFromItemRecord ne le copie pas) ; le seul signal côté desc = `info+0x5d`. **Plugin FAIT** : `ExtractItem` lit `*(u8*)(wnd+0xb8+0x5d)` → `e->name_shadow = (!=0)?IM_COL32(0xFA,0x50,0x50,255):0` ; `DrawTitle(...,shadow)` dessine le nom entier décalé +1,+1 dans l'ombre AVANT le texte (GetWindowDrawList AddText) ; gate d'affichage du nom dans le corps élargie à `header || hl_start>=0 || name_shadow`. ZÉRO hardcode (champ natif). Fidélité restante : ombre grade blanche (info+0x5d==0) non reproduite (invisible sur fond clair).
