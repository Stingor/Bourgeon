# Fenêtre Équipement (id 0xa) : RE et EquipTweaks

> Journal du chantier. La fiche de mémoire `project_equip_window_re` n'en garde que l'état et les règles.
> Extrait le 2026-09-04 de la mémoire ; contenu historique, non revérifié.

Full RE of the **Equipment window** on the 20250716 client (Moonlight-Destiny.exe, base 0x400000), done 2026-06-28. Goal = widen it so item names aren't truncated + other tweaks. Opened by the **equip menu icon (cmd 0xC3 -> FUN_00814a70 case 0xc3 -> FUN_00812e60(0xa))**.

## Identity
- **Window ID = 0xa.** ctor **UIWnd_id0a_ctor 0x0088d740**, vtable **0x0103223c** (PTR_FUN_0103223c). Own instance cached at **g_UIWindowMgr(0x0131f4e8)+0x1e0 = 0x0131f6c8**; the "view another player's equip" instance cached at g_UIWindowMgr+0x3fc (mode flag this+0xb4=1).
- **Mode flag `this+0xb4`**: 0 = OWN equip (full interactive: tabs, checkboxes, damage-indicator editor); !=0 (1) = viewing ANOTHER player's equip (read-only). Tons of `if(this+0xb4==0)` guards in OnCreate/DrawContent/WndProc.
- **DEFAULT SIZE = 280 x 167** (0x118 x 0xa7). Set in MakeWindow: own @ width imm **0x00a3a2e3** (push 0x118) + height imm 0x00a3a2d8 (push 0xa7), cached [edi+0x1e0], 0xb4=0. Other-player view @ width imm 0x00a3f0f5 + height 0x00a3f0d8, cached [edi+0x3fc], 0xb4=1. SetSize=0x00a1cb70 (w@+0x14,h@+0x18).

## *** THE SLOT GRID = FUN_00897d60 (the key fn for widen-to-see-names) ***
Loops slot index uVar8 = 0..9 (10 slots). Per slot fetches equipped item: General-own=**FUN_00d59b90(session,&buf,slot)**, General-other=FUN_00d5d040, Costume-own=FUN_00d800b0, Costume-other=FUN_00d81c70. If slot has item (local_528!=0) and drawable (local_51c==1):
- **ICON** via FUN_00871040(this, X, Y, &item). For slots 0-7: X = column x from local_53c[] = **{6 (left col), 0xfb=251 (right col)}** picked by (slot&~3); Y = (slot&3)*0x1a + this+0xf4 + 0x2c. Slots 8-9 (top row): X=local_53c[slot&3], Y=this+0xf4+0x12.
- **NAME TEXT** via **FUN_008976a0(this, textX+5, Y2, 0x46, &item, 0,0, 0xc)**. textX from local_54c[] = **{0x1c=28 (left), 0xa7=167 (right)}**; +5 => name x = **33 (left) / 172 (right)**. Y2 = this+0xf4 + local_24[row] + 0x33 (local_24 = rdata _DAT_01037250 row offsets). **WIDTH CAP = 0x46 = 70px** (param_3) -> this is WHY names truncate ("Protection Co at"). Font size 0xc.
- A small status/enchant icon (FUN_00a94930 fmt DAT_0101fb6c path) blitted next to it; and an "empty/blocked" overlay (DAT_01035d28) when FUN_00d60f10 says slot locked.
- **FUN_008976a0** = name string builder+drawer: FUN_008a0570 builds "name (+refine) [cards]" into 256-buf; **FUN_006a2990(item)=quality color** (0xadff2f green remapped to 0x669900); **FUN_008d0270(this,&x,text,len,color,...,WIDTH=param_3,...)** = the width-bounded draw (truncates to WIDTH). To show full names: raise the 0x46 width + move right column + widen window.

## *** DRAG/GRIP HIT-TEST (the interactive slot position) — separate from tooltip! ***
LIVE 2026-06-28: **right-click = item TOOLTIP only (NOT unequip)**; you unequip/move by **left-click GRIP + drag** to inventory. So moving the icon DRAW without the drag hit-test = "items grip at the old empty spot" (the user's bug).
- **Main Equip drag/grip hit-test = FUN_0089e460** (used by drag-grab FUN_008b95b0 vtable+0x64 -> starts drag via FUN_00c938e0; and click FUN_008b9110 vtable+0x68). Unlike the tooltip/right-click hit-test FUN_0089ec70 (zone-based, follows width), FUN_0089e460 uses **TIGHT hardcoded ICON RECTS**: left x[6,30], **right x[251,275]** (= stock icon). Column split = `x/251` (magic-compiled, NOT a patchable literal). FIX (EquipTweaks 3b): shift the right rect base — `lea eax,[edi-0xfb]` disp32 @**0x0089e4c8** from -251 to -(251+extra); the x/251 split still buckets the moved icon (311) as right. Left rect [6,30] unchanged (left icon not moved). General+Costume share FUN_0089e460.
- **Hover-highlight (item_invert.bmp) right x = 0xf8=248** hardcoded in DrawContent `mov [ebp-0x128],0xf8` @**0x008b3427** -> +extra (follows the icon, box is icon-3).
- **SWAP window drag hit-test = FUN_007f8e80** (used by FUN_007f99c0 vtable+0x64) is DIFFERENT: **zone-based** like the tooltip (left[6,0x69], right[0xaa, width-6], slot by row) -> **auto-follows the widening, NO patch needed**. (Confirmed by user: "swap doesn't have a hit zone to modify, it's just General and Costume".) The two windows' drag hit-tests are coded differently — Equip tight-rect, Swap zone.

## PLUGIN EquipTweaks — BUILT 2026-06-28 (src/plugins/equip_tweaks.{cc,h}, registered bourgeon.cc after InventoryTweaks, in CMakeLists)

- window width push 0x118 imm32: OWN @**0x00a3a2e4**, OTHER-view @**0x00a3f0f6** (NB: push opcode 0x68 at 0xa3a2e3, imm32 at +1) -> 280+extra.

Right NAME x: mov imm32 0xa7=167 @**0x00897e05** -> 167+kRightNameShift (=33 -> 200, drawn at 205). **LESSON (live 2026-06-28): KEEPING right name at 167 = WRONG — the avatar is centred at width/2 and grows with the window, so the right name drew ON TOP of the enlarged avatar ("Protection Coat" over the sprite). Must shift the right name right by ~deltaW/2 to clear it.** Left icon 6 / left name 28 kept.
- name width cap push imm8 0x46=70 @**0x00897ffb** -> kNameCap (=**127**, the HARD MAX: it's a `push imm8` that sign-extends, so 0x80+ = negative width = broken). **The name renderer FUN_008976a0->FUN_008d0270 WRAPS the text to up to 3 lines at this width** (measures per-char, breaks lines), so BIGGER cap = FEWER wrap-lines (the costume-tab long-name 2-line overlap fix = raise the cap). The centred avatar (doll FUN_007ac820) is drawn AFTER the slots, so left-column name overflow is HIDDEN behind the character (clean); the right column name can overlap its icon (~311) for very long names.
