## ⚠️ SHUFFLE opcodes (clif_shuffle.hpp) — leçon 2026-07-09 (disconnect au drop)
Le serveur moonlight applique **clif_shuffle.hpp APRÈS clif_packetdb.hpp** => opcodes REMAPPÉS. Le shuffle **AJOUTE** des opcodes sans retirer ceux du packetdb (=> 0x08ac dépôt storage marche TOUJOURS) mais **RÉÉCRIT** les opcodes sensibles (skill/drop…). Bloc actif 20250716 = **`#elif PACKETVER > 20180307`** (+ nested `>= 20220330`). Pour l'inventaire :
- **DROP** : 0x0438 (packetdb) est RÉÉCRIT `UseSkillToId` len 10 par le shuffle -> disconnect « expected 10, got 6 ». **Vrai drop = 0x0363** (shuffle, `[op:2][index:2][amount:2]`). **FIXÉ kOpDrop=0x0363**.
- **Favori 0x0907** : PAS dans le shuffle -> OK. **Use/equip/transfert** = via DISPATCHER (le client applique le shuffle lui-même) -> JAMAIS touchés (d'où : seul le drop hardcodé cassait).
- **LEÇON** : le workflow RE opcodes n'a vérifié QUE le packetdb -> faux pour les opcodes shufflés. TOUJOURS croiser clif_shuffle.hpp. cf [[project_opcode_system]] [[project_storage_window_re]] (0x0128/0x0129 « pas remappés par le shuffle »).
